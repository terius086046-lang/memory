## 1. AI 기반 견적 생성을 위한 핵심 프롬프트 구조 (The Engine Prompt)

사용자가 입력한 비정형 데이터를 가장 정확하고 일관성 있게 처리하여 **구조화된 비용 데이터**를 산출하도록 AI 모델을 강제하는 마스터 프롬프트입니다. 이 프롬프트는 시스템의 모든 추론 로직의 기반이 됩니다.

### 📝 마스터 프롬프트 (Master Prompt) 상세 설계

이 프롬프트는 **역할 정의, 입력 데이터 정의, 처리 규칙(가장 중요), 그리고 출력 형식**을 명확히 분리하여 LLM이 단순한 대화가 아닌 '계산기'처럼 작동하게 만듭니다.

```prompt
# 🛠️ 시스템 역할 및 목표 (System Role & Objective)
당신은 국내 인테리어 및 건축 분야의 최고 수준의 전문 비용 분석가(Senior Cost Analyst)이자, 설계 데이터와 현장 제약을 기반으로 오류 없이 합리적인 최종 비용 견적을 산출하는 AI 엔진입니다. 당신의 유일한 목표는 입력된 모든 정보를 분석하여 '견적 보고서'라는 구조화된 결과물을 생성하는 것입니다.

# 📥 입력 데이터 (Input Data)
당신은 다음 세 가지 유형의 데이터를 반드시 통합적으로 분석해야 합니다:
1. [기존 견적서]: 과거 프로젝트의 비용 산정 패턴, 적용된 단가 구조 및 마진율을 분석하여 일관성을 확보합니다. (참조용)
2. [설계도/도면 데이터]: 공간의 치수(길이, 면적), 구조(벽체, 기둥 위치), 레이아웃, 재료 사양(바닥재, 벽체 종류) 등 모든 시각적 및 치수 정보를 분석합니다. (물리적 제약 조건)
3. [현장 특성 데이터]: 현장의 환경(층고, 구조적 제약 조건, 특수 요구사항), 사용된 자재의 실제 품질 수준, 시공 난이도, 예상되는 추가 공정 리스크 등을 포함합니다. (비용 변동 요인)

# ⚙️ 처리 규칙 및 논리 (Processing Rules & Logic - **최우선 준수**)
1. **제약 조건 기반 추론:** 모든 비용 산출은 [설계도]와 [현장 특성 데이터]에서 정의된 물리적, 구조적 제약을 절대적인 기준으로 삼아야 합니다. 임의적인 가정을 배제하고, 누락된 정보는 반드시 '추정 범위'로 명시해야 합니다.
2. **변동 비용 반영:** [현장 특성 데이터]에 명시된 모든 변수(예: 특정 자재 사용 불가, 추가 보강 필요)를 견적 항목의 비용 산출 시점에 직접적으로 반영하여 조정합니다.
3. **구조화된 분류:** 최종 결과물은 반드시 공정별(철거, 목공, 설비, 마감 등)로 명확히 분류하고, 각 항목을 '재료비', '인건비', '부자재'로 세분화하여 제시해야 합니다.
4. **투명성 확보:** 최종 견적 내역의 모든 수치에는 해당 비용이 어떤 입력 데이터(예: 도면상의 특정 면적, 현장 특성 조건)에서 기인했는지에 대한 근거를 명시하는 메타데이터를 포함해야 합니다.

# 📤 출력 형식 (Output Format - **JSON Strict Mode**)
최종 결과물은 반드시 아래의 JSON 스키마를 엄격하게 준수하여 반환해야 합니다. 다른 설명 없이 오직 JSON만 출력합니다.

{
  "project_summary": "프로젝트 요약 및 핵심 제약 조건 요약",
  "cost_breakdown": [
    {
      "phase": "철거 및 준비",
      "details": [
        {"item": "...", "material": "...", "quantity": "...", "unit_cost": "...", "total_cost": "...", "justification": "데이터 근거"}
      ]
    },
    {
      "phase": "목공 및 구조",
      // ... 나머지 공정 항목들
    }
  ],
  "summary_metrics": {
    "estimated_total_cost": "[총 추정 비용]",
    "risk_assessment": "[주요 리스크 요인 및 조정 근거]"
  },
  "disclaimer": "본 견적은 AI 기반 자동화 시스템으로, 최종 시공 전 현장 확인을 통해 확정되어야 합니다."
}
```

## 2. MVP 아키텍처 설계 (Data Pipeline & Architecture)

최종 결과물(견적서)을 API로 제공하기 위해서는 파일 처리부터 LLM 추론까지의 안정적인 파이프라인 구축이 필수입니다.

### 🏗️ 시스템 아키텍처 개요 (MVP Focus)

| 레이어 | 주요 기술/역할 | 상세 기능 및 데이터 흐름 |
| :--- | :--- | :--- |
| **1. 프론트엔드 (Presentation)** | React/Next.js, TypeScript | 사용자 인터페이스 제공. 파일 업로드 및 결과 다운로드 관리. |
| **2. 백엔드 API (Application)** | Python (FastAPI/Django), Node.js | 사용자 요청 처리, 데이터 유효성 검사, LLM 호출 관리, DB 연동. |
| **3. 데이터 파이프라인 (Ingestion & Processing)** | Python, OpenCV/Tesseract, Vision API (선택) | 파일 업로드 → 이미지/PDF 추출 및 OCR 수행 → 데이터 정규화 및 구조화 → 프롬프트 포맷팅. |
| **4. AI 엔진 (Core Logic)** | LLM (GPT-4o 또는 Claude 3 Opus), RAG (선택) | **마스터 프롬프트**를 기반으로 입력 데이터를 분석하고 JSON 형식의 견적 데이터 생성. |
| **5. 데이터베이스 (Storage)** | PostgreSQL/MongoDB | 사용자 정보, 프로젝트 메타데이터, 최종 생성된 **구조화된 견적 결과물(JSON)** 저장 및 관리. |

### 🔗 데이터 파이프라인 상세 흐름

1.  **파일 업로드:** 사용자가 웹 인터페이스를 통해 `[견적서 PDF]`, `[설계도 JPG]` 및 `[현장 특성 텍스트 파일]`을 업로드합니다.
2.  **Pre-processing (Vision/OCR):** 백엔드가 업로드된 이미지/PDF를 수신하여 Vision API 또는 OCR 기술(예: Tesseract, Google Vision)을 사용하여 **정량적 데이터(면적, 치수)**와 **비정형 텍스트**를 추출합니다.
3.  **Data Structuring (Normalization):** 추출된 비정형 데이터를 LLM이 이해하기 쉽도록 정규화하고, 이를 마스터 프롬프트의 `Input Data Definition`에 맞춰 구조화된 텍스트(혹은 JSON)로 변환합니다.
4.  **Prompt Injection:** 정규화된 데이터와 사용자의 최종 요청을 조합하여 **마스터 프롬프트**를 완성합니다.
5.  **LLM Inference (Core Calculation):** 완성된 프롬프트를 LLM에 전달하여, 추론 및 계산을 수행하고 지정된 JSON 형식의 견적 결과를 반환받습니다.
6.  **Storage & API Delivery:** 생성된 JSON 결과물을 데이터베이스에 저장하고, 사용자가 요청한 엔드포인트(API)를 통해 최종 견적서를 제공합니다.

## 3. 서비스 모델 및 고객 확보 전략 (Business Model & Acquisition)

이 자동화 툴을 성공적으로 시장에 출시하기 위해서는 단순 기능 제공을 넘어선 **가치 기반의 구독 모델**이 필수적입니다.

### 💰 수익화 모델 제안 (Monetization Strategy)

| 모델 | 설명 | 장점 | 단점 | 추천 단계 |
| :--- | :--- | :--- | :--- | :--- |
| **Freemium + Credit System (추천)** | 기본 분석은 무료 제공. 고해상도 이미지 처리, 복잡한 구조 분석, 다중 프로젝트 처리는 크레딧 기반 유료 구독(SaaS)으로 제한. | 초기 사용자 확보 용이. 사용량에 따른 명확한 비용 책정 가능. | 시스템 인프라 및 API 호출 비용 관리 필요. | MVP 출시 시점 |
| **Subscription Tier (구독형)** | 월별/연간 구독료 기반. 제공하는 기능 레벨(기본 견적, 고급 자재 분석, 자동 보고서 생성 등)에 따라 티어를 나눔. | 안정적인 MRR 확보 가능. 고객 생애 가치(LTV) 증가. | 초기 시장 진입 시 잠재 고객의 지불 의사 확인 필요. | Post-MVP 확장 시점 |
| **Pay-per-Quote (건당 과금)** | 견적서 하나당 또는 프로젝트 규모당 비용 청구. | 높은 가치를 제공하는 만큼 직접적인 수익 창출이 명확함. | 고객이 견적 요청을 망설일 수 있음. | 특정 전문 분야 집중 시점 |

### 🚀 고객 확보 및 서비스 방식 (Acquisition & Delivery)

#### A. 웹 서비스 방식 (Web Service - MVP 최적화)
**방식:** 사용자 친화적인 단일 대시보드 중심의 파일 업로드 시스템.

*   **Flow:** 홈페이지 접속 → 로그인/가입 → '견적 생성' 탭 선택 → **다중 파일(도면, 현장 정보 등) 드래그 앤 드롭 업로드** → 필요 항목 체크 → AI 분석 요청 → 결과 확인 및 다운로드 (PDF/Excel).
*   **장점:** 데이터 처리 파이프라인을 가장 효율적으로 구축할 수 있으며, 대용량 파일 처리에 용이함.
*   **적합 대상:** 인테리어 회사, 소규모 건축사무소 등 전문적인 B2B 사용자.

#### B. 모바일 앱 방식 (Mobile App - 확장 단계)
**방식:** 현장 작업에 최적화된 기능(Field Work Mode) 제공.

*   **Flow:** 모바일에서 현장 사진 촬영 및 위치 지정 → 현장에서 바로 필요한 특성 데이터 입력 → 업로드된 파일 자동 분석 요청 → 결과 수신.
*   **장점:** 현장 실시간 데이터 수집에 강점. 현장 작업자가 직접 데이터를 입력하여 견적을 생성하는 워크플로우에 적합.
*   **단점:** 초기 MVP 단계에서는 웹보다 개발 복잡도가 높고, 대용량 파일 처리 시 불안정할 수 있음.

### 🎯 최종 권고 사항

**MVP는 반드시 '웹 서비스'로 시작해야 합니다.** 데이터 파이프라인의 핵심은 **파일 업로드와 LLM 추론의 정확성**이며, 이는 웹 인터페이스를 통해 사용자가 데이터를 명확하게 제공할 때 가장 효과적으로 검증될 수 있습니다. 초기에는 견적 보고서의 *정확도*와 *신뢰성*에 모든 개발 역량을 집중해야 합니다.
