## 1. AI 시스템을 위한 핵심 엔진 프롬프트 (The Engine Prompt)

이 프롬프트는 사용자가 업로드하는 비정형 데이터를 분석하여, **일관성, 정확성, 전문성**을 극대화한 최종 견적 보고서를 생성하도록 설계되었습니다. 이는 사용자 명령(견적 자동화)의 핵심 로직이 됩니다.

### 📝 마스터 프롬프트 (Master Prompt)

```prompt
# 역할 정의 (Role Definition)
당신은 국내 인테리어 및 건축 분야에서 최소 10년 이상의 경력을 가진 최고 수준의 전문 비용 분석가(Senior Cost Analyst)이자, 설계 데이터를 기반으로 현실적인 견적을 산출하는 AI 컨설턴트입니다. 당신의 목표는 입력된 모든 정보를 분석하여 오류 없이 일관되고 전문적인 최종 비용 견적 보고서를 생성하는 것입니다.

# 핵심 목표 (Objective)
업로드된 [기존 견적서], [설계도/도면], [현장 특성 데이터]를 종합적으로 분석하여, 프로젝트의 범위와 요구사항에 완벽하게 부합하는 상세하고 합리적인 최종 비용 견적 보고서를 산출하는 것입니다.

# 입력 데이터 정의 (Input Data Definition)
다음 세 가지 유형의 데이터를 반드시 분석에 활용해야 합니다:
1. [기존 견적서]: 과거 프로젝트의 비용 산정 패턴, 적용된 단가 구조 및 마진율을 분석하여 일관성을 확보합니다.
2. [설계도/도면]: 공간의 크기, 구조(벽체, 기둥 위치), 레이아웃, 재료 사양(바닥재, 벽체 종류)을 파악합니다. (시각적 정보 및 치수 정보 분석)
3. [현장 특성 데이터]: 현장의 환경(층고, 구조적 제약 조건, 특수 요구사항), 사용된 자재의 실제 품질 수준, 시공 난이도, 예상되는 추가 공정 리스크 등을 포함합니다. (정성적/정량적 제약 조건 파악)

# 처리 규칙 및 논리 (Processing Rules & Logic)
1. **일관성 최우선:** 모든 비용 산출은 [설계도]와 [현장 특성 데이터]의 물리적 제약을 절대적으로 준수해야 하며, 임의적인 추측이나 가정을 배제해야 합니다.
2. **Pain Point 반영 및 조정:** [현장 특성 데이터]에서 언급된 모든 제약 조건(예: 특정 자재 사용 불가, 구조 보강 필요)을 견적 항목에 비용 조정 요소로 명확히 반영하고 그 근거를 제시합니다.
3. **표준화된 분류:** 산출 내역은 단순 목록이 아닌, 공정별(철거, 목공, 설비, 마감 등)로 명확히 분류하고 세부 항목(재료비, 인건비, 부자재 포함)을 구분하여 제시해야 합니다.
4. **투명성 확보:** 최종 견적 내역의 각 항목에 대해, 해당 비용이 어떤 입력 데이터(도면의 특정 치수, 현장 특성 조건 등)에서 도출되었는지 추적 가능한 메타데이터를 반드시 포함해야 합니다.
5. **불확실성 보고:** 견적 산출에 있어 데이터 부족으로 인해 판단이 필요한 부분이나 모순되는 정보가 발견될 경우, 해당 부분을 명확히 표시하고 사용자에게 재확인을 요청해야 합니다.

# 출력 형식 (Output Format)
결과는 다음의 마크다운 구조를 엄격하게 따르며, 최종적으로 총 견적 금액을 명시해야 합니다.
1. **요약 보고서:** 프로젝트 개요 및 주요 가정 사항 요약.
2. **세부 산출 내역 테이블:** 공정별(Phase)로 분류된 상세 비용 항목 (재료비, 인건비, 부자재).
3. **분석 근거:** 각 주요 항목에 대한 데이터 출처(Source Data Reference) 및 적용 논리 설명.
4. **총 견적 요약:** 최종 금액 및 견적의 신뢰도 점수 (10점 만점).
```

## 2. 사용자 여정 (User Flow) 설계: '아키텍트 대시보드' 기반

사용자가 자료를 업로드하고 견적을 받는 과정을 **최소한의 클릭과 최대의 명확성**으로 압축하는 4단계 프로세스를 제안합니다.

### 🗺️ 단계별 사용자 여정 (User Journey)

| 단계 | 사용자 행동 (Action) | 시스템 상태 (System State) | 디자인 목표 (Design Goal) |
| :--- | :--- | :--- | :--- |
| **Step 1: 진입 및 설정** | 홈페이지 접속 후, 프로젝트 유형(주거/상업/리모델링 등) 선택. | 초기 데이터 수집 모듈 활성화. | 명확한 시작점 제시 및 신뢰감 구축. |
| **Step 2: 데이터 업로드 (핵심)** | ① 기존 견적서 업로드 ② 설계 도면(PDF/CAD) 업로드 ③ 현장 특성 입력 (폼 또는 AI 분석). | 모든 원천 데이터 시스템에 저장 및 AI 분석 대기 상태 진입. | 파일 업로드 과정의 피드백 제공 (Progress Bar), 데이터 연관성 강조. |
| **Step 3: AI 분석 및 검토** | '견적 생성 시작' 버튼 클릭 후, AI가 내부적으로 데이터를 처리하는 시간 동안 대기. | AI 엔진이 마스터 프롬프트에 따라 데이터 간의 논리적 모순을 검토하고 비용 계산 수행. | 진행 상황 시각화 (Loading State), 잠재적 오류 알림 기능 제공. |
| **Step 4: 결과 확인 및 확정** | 최종 견적 보고서(아키텍트 대시보드)를 확인하고, 각 항목의 근거를 검토 후 최종 승인. | 최종 결과물 저장 및 다운로드 기능 활성화. | 투명한 데이터 시각화 (Glassmorphism 적용), 쉬운 수정 옵션 제공. |

## 3. '아키텍트 대시보드' UI/UX 목업 컨셉 (Neo-Glassmorphism)

**스타일:** 네오-글래스모피즘 (Neo-Glassmorphism)
**핵심 원칙:** 투명성(Transparency)을 통해 데이터의 근거를 드러내어 **권위(Authority)**와 **신뢰도**를 확보합니다.

### 🖥️ 대시보드 레이아웃 및 컴포넌트 설계

#### A. 전체 스타일 가이드

*   **배경:** 미니멀하고 어두운 모드 (Deep Navy 또는 Charcoal Gray)를 사용하여 콘텐츠에 집중하게 합니다.
*   **Glass Effect:** 모든 주요 카드(견적 항목, 요약 정보)는 반투명한 흰색/밝은 회색 배경과 낮은 불투명도(Opacity: 10% ~ 20%)를 적용하여 배경이 은은하게 비치도록 설계합니다. 이는 '데이터의 투명성'을 시각화합니다.
*   **Border:** 미세하고 밝은 테두리(Light Border)를 사용하여 유리처럼 입체감을 부여합니다.
*   **Typography:** 산세리프 계열 (예: Inter, Pretendard)을 사용하여 기술적이고 현대적인 느낌을 강조하며, 중요 수치는 굵고 명확하게 표시합니다.

#### B. 핵심 화면 구성 (The Architect Dashboard)

1.  **상단 헤더 (Header):** 프로젝트명, 현재 상태(In Progress/Completed), 빠른 액션 버튼(다운로드, 수정).
2.  **좌측 패널 (Context Panel - Glassmorphism):**
    *   **데이터 근거 요약:** "이 견적은 [설계도 A]와 [현장 특성 B]를 기반으로 산출되었습니다." 와 같이 AI의 추론 과정을 투명하게 보여줍니다.
    *   **KPI 대시보드:** 예상 비용, 공정별 지연 위험도 등 핵심 지표를 시각화합니다.
3.  **중앙 메인 영역 (Core Visualization):**
    *   **상세 견적 테이블:** 가장 중요한 부분. 각 항목은 **Glass Card** 형태로 분리되며, 클릭 시 해당 항목에 대한 상세 계산 로직(프롬프트 규칙)을 팝업으로 보여줍니다.
    *   **비주얼 비교:** 설계도와 최종 견적의 주요 영역이 오버레이되어 표시되도록 하여 '무엇을 기준으로 비용이 산정되었는지'를 즉각적으로 확인하게 합니다.

### 💡 UI/UX 핵심 시각화 예시 (Mockup Concept)

*   **데이터 흐름 시각화:** 왼쪽 패널에 업로드된 세 가지 원천 파일(견적서, 도면, 특성)이 중앙 견적 결과로 흐르는 화살표를 투명한 선으로 표현하여 데이터의 연결고리를 직관적으로 보여줍니다.
*   **비용 분해 시각화:** 전체 비용을 막대 그래프나 파이 차트로 분할하고, 각 구간(마감재, 구조, 인건비 등)에 Glassmorphism 카드를 배치하여 비용 구성의 투명성을 극대화합니다.

## 4. 서비스 제공 방식 및 수익화 전략

고객(인테리어 회사/시공사)의 특성상 **신뢰도**와 **정확성**이 가장 중요한 구매 결정 요소입니다. 따라서 웹과 앱 중 어떤 방식을 선택하느냐에 따라 접근 방식이 달라져야 합니다.

### 🌐 서비스 형태 비교 분석

| 구분 | 웹 서비스 (Web Application) | 모바일 앱 (Native/Hybrid App) |
| :--- | :--- | :--- |
| **접근성** | 높음 (PC 기반 작업 환경에 최적화) | 중간 (현장이나 이동 중 사용에 용이) |
| **데이터 처리** | 복잡한 파일 업로드 및 다중 문서 분석에 유리. AI 엔진 구동에 적합. | 실시간 데이터 입력과 현장 사진/도면 촬영 기능에 유리. |
| **UX/UI** | 대시보드 형태의 깊이 있는 분석 화면 제공에 최적화됨. | 모바일 환경 제약으로 인해 복잡한 데이터 시각화가 어려울 수 있음. |
| **수익화 적합성** | **높음.** 최종 보고서 및 관리 기능(CRM 연동) 판매에 유리함. | 중간. 보조적인 현장 체크리스트 역할에 집중해야 함. |
| **추천 방식** | **핵심 견적 자동화 시스템의 메인 플랫폼**으로 구축. | 현장 검증, 실시간 자재 확인 등 보조 기능으로 활용. |

### 💰 수익화 모델 제안 (Monetization Strategy)

단순히 '견적 생성'을 넘어, 고객이 이 툴을 **'프로젝트 관리 시스템(PMS)'**으로 인식하게 만들어 구독 및 프리미엄 판매를 유도해야 합니다.

1.  **Freemium 모델 (기본 접근):**
    *   **Free Tier:** 월별/프로젝트당 제한된 횟수의 기본 견적 생성 및 단순 데이터 저장 기능 제공. (사용자 확보)
    *   **Pro Tier (핵심 수익):** 무제한 프로젝트, 고급 분석 모듈(구조적 리스크 자동 감지), CRM 연동 기능, 팀원 협업 기능 제공. (전문가 타겟 유료화)

2.  **결과 기반 판매 모델 (Value-based Pricing):**
    *   **견적서 프리미엄 패키지:** AI가 산출한 견적서 외에, **'법규 준수 보고서', '리스크 분석 보고서'**와 같은 고부가가치 문서를 추가 옵션으로 제공하여 단가를 높입니다.
    *   **템플릿 판매:** 성공적으로 생성된 표준화된 견적 템플릿(네오-글래스모피즘 디자인 적용)을 프리미엄으로 판매합니다.

3.  **B2B 솔루션 모델 (SaaS 연동):**
    *   견적 결과를 내부 프로젝트 관리 시스템(PMS)이나 ERP와 API로 연동할 수 있는 기능을 제공하여, 고객이 견적 후 다음 단계의 관리를 툴 내에서 완료하도록 유도합니다. 이는 **데이터 생태계 전체를 소유**하는 것으로 인식되어 이탈률을 낮춥니다.
