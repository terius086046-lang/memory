### 1. 핵심 AI 프롬프트 구조 설계 (The Engine Prompt)

AI가 업로드된 비정형 데이터(도면, 현장 특성)를 분석하여 일관되고 전문적인 견적서를 생성하도록 지시하는 **마스터 프롬프트**의 구조입니다. 이 프롬프트는 **역할 정의, 입력 데이터 정의, 처리 규칙, 출력 형식**으로 명확하게 분리되어야 합니다.

#### 📝 마스터 프롬프트 (Master Prompt) 예시

```prompt
# 역할 정의 (Role Definition)
당신은 국내 인테리어 및 건축 분야의 최고 수준의 전문 견적 분석가(Senior Estimator)이자, 데이터 기반 의사결정을 지원하는 AI 컨설턴트입니다. 당신의 목표는 업로드된 모든 설계 정보와 현장 특성 데이터를 분석하여, 오류 없이 일관되고 전문적인 비용 견적서를 생성하는 것입니다.

# 핵심 목표 (Objective)
업로드된 [설계도], [현장 특성 데이터], [기존 견적서]를 종합적으로 분석하여, 프로젝트의 범위와 요구사항에 완벽하게 부합하는 상세하고 합리적인 최종 견적서를 산출하는 것입니다.

# 입력 데이터 정의 (Input Data Definition)
다음 세 가지 유형의 데이터를 반드시 분석에 활용해야 합니다:
1. [설계도/도면]: 공간의 크기, 구조, 배치, 재료 사양을 파악합니다. (시각적 및 치수 정보 분석)
2. [현장 특성 데이터]: 현장의 환경(층고, 구조적 제약 조건, 특수 요구사항), 사용된 자재의 실제 품질 수준, 시공 난이도 등을 포함합니다. (정성적/정량적 제약 조건 파악)
3. [기존 견적서]: 참고할 수 있는 과거 프로젝트의 비용 산정 패턴과 가격 구조를 분석하여 일관성을 확보합니다.

# 처리 규칙 및 논리 (Processing Rules & Logic)
1. **일관성 최우선:** 모든 계산은 입력된 설계도와 현장 특성에 기반해야 하며, 추측이나 임의적인 가정을 최소화해야 합니다.
2. **Pain Point 반영:** [현장 특성 데이터]에서 언급된 제약 조건(예: 특정 자재 사용 불가, 구조적 보강 필요)을 견적 항목에 반영하여 비용을 조정해야 합니다.
3. **표준 적용:** 국내 인테리어/건축 표준 및 시장의 일반적인 단가 구조를 참조하여 합리적인 기준을 설정합니다.
4. **분류 및 상세화:** 산출 내역은 단순 목록이 아닌, 공정별(철거, 목공, 설비, 마감 등)로 명확히 분류하고 세부 항목(재료, 인건비, 부자재 포함)을 구분하여 제시합니다.
5. **불확실성 보고:** 견적 산출에 있어 판단이 필요한 부분이나 데이터가 부족한 항목은 반드시 별도로 명시하고, 해당 부분의 변동 요인을 설명해야 합니다.

# 출력 형식 (Output Format)
결과는 다음의 구조화된 JSON 또는 마크다운 형식으로만 제시되어야 합니다.

## [최종 견적 보고서]
**프로젝트 개요:** [간략한 프로젝트 설명 및 핵심 제약 조건 요약]
**분석 근거:** [입력 데이터 중 어떤 부분을 가장 중요하게 고려했는지 명시]
**상세 산출 내역 (Cost Breakdown):**
- **Phase 1: [철거/구조]**: 세부 항목, 수량, 단가, 금액
- **Phase 2: [목공/설비]**: 세부 항목, 수량, 단가, 금액
- **Phase 3: [마감/인테리어]**: 세부 항목, 수량, 단가, 금액
**총 견적 금액:** [최종 합산 금액 (VAT 별도)]
**참고 사항 및 권고:** [견적에 영향을 미치는 주요 변수 및 다음 단계 제안]
```

### 2. 서비스화 방안 및 수익 모델 제안 (Monetization Strategy)

고객이 이 서비스를 구매하고 지속적으로 사용하도록 유도하기 위해서는 단순한 '결과물 제공'을 넘어 **'신뢰성 확보'와 '워크플로우 통합'**에 초점을 맞춰야 합니다.

#### A. 서비스 형태 비교 분석

| 서비스 형태 | 웹서비스 (SaaS) | 모바일 앱 (Native/Hybrid) |
| :--- | :--- | :--- |
| **사용자 경험 (UX)** | 전문가 중심의 상세한 보고서 및 데이터 시각화에 유리. 복잡한 분석 과정 공유 용이. | 현장 작업자가 즉시 현장에서 자료를 업로드하고 결과를 확인하는 데 직관적. |
| **데이터 처리** | 대용량 도면, PDF 등 복합 파일을 다루기에 적합. 백엔드 시스템 구축 용이. | 카메라 기반 측정이나 간단한 데이터 입력에 특화되어야 함. 파일 업로드 및 관리의 복잡성 발생 가능. |
| **수익 모델** | 구독 기반 (월별/프로젝트당) + 프리미엄 분석 모듈 판매. | 라이선스 기반 또는 프리미엄 기능 잠금 해제 방식. |
| **추천 적합도** | **높음.** 복잡한 전문 견적 프로세스를 자동화하고 신뢰를 구축하는 데 유리함. | 중간. 현장 중심의 빠른 피드백에는 좋으나, 최종적인 '전문성' 전달에는 웹이 더 강력함. |

#### B. 추천 서비스 모델: 하이브리드 SaaS (Web-First)

**핵심 제안:** **웹 기반 SaaS(Software as a Service)**를 메인으로 하고, 현장 작업자의 편의를 위한 모바일 앱은 보조 기능으로 제공하는 하이브리드 전략을 추천합니다. 이는 전문적인 분석 결과를 신뢰성 있게 전달하는 데 가장 효과적입니다.

**1. 핵심 수익 모델: 구독 기반 (Subscription Model)**
*   **Basic Tier (입문자):** 제한된 파일 수, 기본 견적 생성 기능 (개인 또는 소규모 프로젝트용). 월별/연간 구독료 부과.
*   **Pro Tier (전문가용):** 무제한 파일 처리, 고급 분석 모듈(예: 자재 시장 연동 가격 변동 반영), 다중 프로젝트 관리 대시보드 제공. (주요 수익원)
*   **Enterprise Tier (대형사/협력사):** API 연동 기능 제공, 팀 단위 협업 및 내부 데이터베이스 통합 지원.

**2. 차별화된 서비스 방식 (Feature Differentiation)**

| 기능 | 설명 | 고객 가치 |
| :--- | :--- | :--- |
| **AI 기반 정밀 견적 엔진** | 위에서 설계한 마스터 프롬프트가 백엔드에서 구동되어, 모든 데이터 입력에 대해 일관된 계산 결과를 도출. (가장 핵심) | 시간 절약 및 인적 오류 최소화. |
| **자재 시장 연동 모듈** | 실시간 자재 가격 API를 연동하여 견적 시점의 시장 변동을 반영한 '예상 비용 범위' 제공. | 견적의 불확실성 해소 및 리스크 관리. |
| **자동 Q&A/수정 시스템** | 생성된 견적서에 대해 고객이 질문하면 AI가 즉시 근거를 제시하며 수정안을 제안하는 기능. (신뢰도 강화) | 커뮤니케이션 비용 절감 및 신속한 의사결정 지원. |
| **아키텍트 대시보드** | Designer의 목표에 맞춰, 모든 프로젝트 데이터(KPI 측정 포함)를 시각화하여 경영진 및 팀장에게 제공. (itda의 KPI 연계) | 데이터 기반의 의사결정 환경 제공. |
