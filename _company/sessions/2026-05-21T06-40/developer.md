요청하신 대로 Business가 확정한 A/B 테스트 변수에 따른 데이터 흐름 시각화의 기술 구현 가능성을 검토하고 와이어프레임 반영을 준비하기 위한 초기 설계안 및 API 구조를 제시합니다. 이는 **권위 및 통제(Authority & Control)** 가설에 기반하여 이벤트 추적 로직이 어떻게 대시보드에 반영되어야 하는지에 초점을 맞춥니다.

## 1. 데이터 흐름 및 시각화 요구사항 분석 (Feasibility Review)

**목표:** A/B 테스트 변수(그룹 A vs 그룹 B)에 따른 사용자 행동(이벤트)의 추적 경로와 전환율 변화를 명확하게 시각화해야 합니다.

**핵심 데이터 요구사항:**
1.  **사용자 세션 정보 (`user_sessions`):** 사용자가 특정 기간 동안 어떤 활동을 했는지 기록. (MAU, 세션 지속 시간 등)
2.  **이벤트 로그 (`event_log_table`):** A/B 테스트에 직접적으로 영향을 미치는 핵심 이벤트(예: 견적 요청 시작, 도면 업로드 완료, 최종 견적 수신)가 그룹별로 분류되어 기록되어야 함.
3.  **테스트 변수 매핑:** 각 이벤트 로그는 해당 사용자가 속한 A/B 그룹(A 또는 B)을 명확하게 연결해야 합니다.

**구현 가능성:** **높음.** 기존에 설계된 데이터 구조(`user_sessions`, `event_log_table`)를 기반으로, API 엔드포인트와 데이터 파이프라인만 보강하면 원하는 시각화가 기술적으로 충분히 가능합니다. 핵심은 이벤트 발생 시점에 사용자 그룹 정보를 정확하게 기록하는 것입니다.

## 2. API 엔드포인트 및 데이터 구조 제안 (MVP Layer)

시각화를 위해 프론트엔드가 직접 데이터를 요청할 수 있도록 다음 두 가지 핵심 API를 정의하고, 이에 필요한 DB 스키마를 보강합니다.

### A. 데이터베이스 스키마 보강 제안

기존 `event_log_table`에 A/B 테스트 변수를 포함하여 기록하는 구조로 확장합니다.

| 필드명 | 타입 | 설명 | 비고 |
| :--- | :--- | :--- | :--- |
| `session_id` | UUID | 사용자 세션 고유 ID | PK |
| `user_id` | INT | 사용자 ID (외부 연동) | FK |
| `event_name` | VARCHAR | 발생한 이벤트 종류 (예: '견적 요청 시작') | |
| `event_timestamp`| DATETIME | 이벤트 발생 시각 | |
| **`ab_test_group`**| ENUM('A', 'B') | 사용자가 속한 A/B 테스트 그룹 | **핵심 연결 필드** |
| `metadata` | JSON | 추가적인 컨텍스트 정보 (예: 업로드된 파일 이름 등) | |

### B. 핵심 API 엔드포인트 정의

프론트엔드(Designer의 와이어프레임)가 데이터 흐름을 시각화하는 데 필요한 데이터를 제공합니다.

**1. `/api/kpis/ab_comparison` (A/B 그룹 비교 대시보드용)**
*   **목적:** 각 A/B 그룹별 핵심 KPI(전환율, 이벤트 완료율)를 비교하여 시각적으로 보여줍니다.
*   **요청 파라미터:** `time_period` (기간), `event_type` (필터링할 이벤트 종류).
*   **응답 구조 예시:**
    ```json
    {
      "group_A": {
        "total_events": 150,
        "conversion_rate": 0.12 // A 그룹의 전환율
      },
      "group_B": {
        "total_events": 180,
        "conversion_rate": 0.15 // B 그룹의 전환율
      }
    }
    ```

**2. `/api/flow/event_path` (데이터 흐름 시각화용)**
*   **목적:** 특정 이벤트(예: '견적 요청 시작')가 A 그룹과 B 그룹에서 어떻게 분기되었는지 데이터 경로를 추적하여 보여줍니다.
*   **요청 파라미터:** `event_name`, `time_period`.
*   **응답 구조 예시:** (트리 또는 그래프 형태로 시각화하기 용이하도록 계층적 구조)
    ```json
    {
      "event": "견적 요청 시작",
      "flow_by_group": {
        "group_A": [
          {"step": 1, "description": "도면 업로드 완료 (Success)", "count": 50},
          {"step": 2, "description": "AI 견적 생성 시도", "count": 45}
        ],
        "group_B": [
          {"step": 1, "description": "도면 업로드 완료 (Success)", "count": 60},
          {"step": 2, "description": "AI 견적 생성 시도", "count": 30}
        ]
      }
    }
    ```
