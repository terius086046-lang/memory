## 실시간 대시보드 구현을 위한 기술 스택 및 API 연결 최적화 방안

Designer의 시각적 요구사항(권위, 통제감)과 Business의 KPI 목표(MAU 65%, 전환율 30%)를 달성하기 위해, 실시간 데이터 스트리밍 대시보드의 성능, 안정성, 그리고 사용자 경험을 극대화하는 기술 스택 및 API 연결 계획을 최적화합니다.

### 1. 핵심 기술 스택 제안 (Stack Recommendation)

실시간성과 권위 강조라는 목표를 달성하기 위해, 단순한 Polling 방식이 아닌 양방향 실시간 통신(Bi-directional Real-time Communication)을 지원하는 아키텍처를 채택합니다.

| 영역 | 추천 기술 스택 | 선택 근거 (Authority & Real-time) |
| :--- | :--- | :--- |
| **데이터 스트리밍** | **WebSockets (Socket.IO 또는 자체 WebSocket 서버)** | 실시간 데이터의 지연 없이 프론트엔드로 즉각 전달하여 '실시간'이라는 가치를 극대화하고, 권위 있는 통제감을 시각적으로 구현하는 데 필수적입니다. |
| **백엔드/API** | **Node.js (Express) 또는 Python (FastAPI)** | 비동기 처리에 강하며, WebSocket 서버 구축 및 API 엔드포인트 관리가 효율적입니다. 데이터 파이프라인과의 통합 용이성도 높습니다. |
| **데이터베이스** | **PostgreSQL (또는 MongoDB for flexibility)** | KPI 추적을 위한 정형화된 데이터(사용자 여정)와 유연한 이벤트 로그를 모두 처리할 수 있는 안정적인 선택입니다. |
| **대시보드 구현** | **React / Next.js + D3.js / Recharts** | Neumorphism 및 색상 시스템(`Primary Blue`, `Accent Teal`)을 컴포넌트 레벨에서 일관되게 적용하고, 데이터 시각화의 입체감(Depth)을 효과적으로 구현합니다. |

### 2. API 연결 및 데이터 파이프라인 최적화 방안 (API & Pipeline Optimization)

KPI 달성과 실시간 요구사항을 충족시키기 위해, 데이터 흐름을 **'스트리밍 → 처리 → 시각화'**의 세 단계로 분리하고 각 단계에서 안정성을 확보합니다.

#### A. 데이터 수집 및 스트리밍 계층 (Ingestion Layer)

1.  **이벤트 발행:** 사용자 행동(클릭, 전환 등)은 백엔드 시스템에 **WebSocket 서버**를 통해 직접 스트림됩니다. 이는 가장 빠른 데이터 전달 경로입니다.
2.  **데이터 파이프라인 통합:** 기존의 데이터 파이프라인(`sessions` 테이블 기록)에서 발생하는 이벤트는 별도의 **메시지 큐(예: RabbitMQ 또는 Kafka)**를 경유하여 WebSocket 서버로 푸시되도록 설계합니다. 이는 스트리밍 중 부하 발생 시 시스템 전체의 안정성을 보장합니다.

#### B. API 연결 및 권한 관리 (API & Security)

1.  **API 게이트웨이:** 모든 데이터 요청과 실시간 연결은 단일화된 API 게이트웨이를 통해 관리하여 보안 취약점을 최소화하고 접근 권한을 중앙에서 통제합니다.
2.  **데이터 집계 API:** 대시보드에 표시될 핵심 KPI(MAU, 전환율)는 **실시간 스트림 데이터** 외에도 정기적으로 (예: 5분 간격) DB에서 집계하여 제공하는 별도의 RESTful API를 운영합니다. 이는 실시간 데이터의 부하 없이 안정적인 통제감을 제공합니다.

#### C. 시각화 최적화 (Visualization Optimization)

1.  **상태 기반 레이아웃:** Designer가 제시한 Neumorphism과 색상 체계를 적용할 때, **데이터의 상태(Health Check)**에 따라 대시보드 섹션이 동적으로 활성화/비활성화되도록 구현합니다. 예를 들어, 시스템 오류 시 Primary Blue 영역이 경고색으로 전환되어 사용자가 즉각적인 조치를 취하도록 유도합니다.
2.  **권위 강조 적용:** 핵심 KPI(Accent Teal)는 가장 큰 볼드체로 처리하고, 나머지 정보는 Primary Blue의 깊은 그림자(Neumorphism) 속에 배치하여, 사용자의 시선이 **'행동해야 할 곳'**에만 집중되도록 설계합니다.

### 3. 실행 계획 요약 (Action Plan Summary)

1.  **인프라 설정:** Node.js 기반 WebSocket 서버와 PostgreSQL 데이터베이스를 초기 환경에 배포합니다.
2.  **스트리밍 구현:** 사용자 이벤트 발생 시, DB 기록과 동시에 WebSocket을 통해 데이터를 실시간으로 전송하는 로직을 구현합니다.
3.  **프론트엔드 통합:** React 컴포넌트에서 WebSocket 연결을 수신하여, Designer의 디자인 시스템(색상 및 Neumorphism)에 맞춰 KPI를 동적으로 렌더링하도록 코드를 작성합니다.
