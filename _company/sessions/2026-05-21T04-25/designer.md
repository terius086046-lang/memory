## 🏛️ 아키텍트 대시보드 최종 디자인 명세 및 사용자 흐름 (Developer 요청용)

본 문서는 '시스템 구축 권한'을 시각화하는 **네오-글래스모피즘(Neo-Glassomorphism)** 기반의 아키텍트 대시보드에 대한 최종 디자인 명세, 와이어프레임 구조, 그리고 개발팀이 즉시 구현할 수 있는 필수 확인 항목 목록(User Flow)을 제공합니다.

### 1. 비주얼 시스템 요약 (Visual System Recap)

**스타일:** 네오-글래스모피즘 (Neo-Glassomorphism)
**핵심 원칙:** 투명함(Frosted Glass)과 권위(Gold Accent)의 결합. 사용자가 시스템 내부를 '엿보는' 듯한 느낌을 주어, 데이터에 대한 접근 권한과 통제감을 강조합니다.

| 요소 | 상세 정의 | 적용 값 (Actionable Data) |
| :--- | :--- | :--- |
| **배경/카드** | 투명도 설정으로 시스템 내부의 데이터를 은은하게 비침. | `Background Opacity`: 15% - 25% |
| **액센트 색상** | 권위와 신뢰감을 부여하는 핵심 강조색. | `Primary Accent (Gold)`: `#FFD700` (약간 채도를 낮춘 `#C6A03A`) |
| **보조 색상** | 데이터 상태 표시 및 배경 처리. | `Secondary Background`: `#1a1a2e` (짙은 네이비/블랙 계열) |
| **타이포그래피** | 시스템 권위 강조를 위한 폰트 선택. | `Font Family`: 'Inter' 또는 'Poppins' (산세리프, 모던함) |
| **보더/경계** | 투명한 카드에 명확성을 부여. | `Border Style`: Subtle, Soft Shadow (Soft Drop Shadow) |

---

### 2. 아키텍트 대시보드 와이어프레임 구조 (Layout Blueprint)

대시보드는 크게 세 구역(Header, Core Metrics, System Access)으로 구성되며, 모든 요소는 투명한 카드 형태로 배치됩니다.

#### A. 헤더 영역 (Navigation & Authority)
*   **레이아웃:** 상단 고정 바 (Fixed Top Bar).
*   **구성 요소:**
    1.  **시스템 권한 표시 (Authority Indicator):** 좌측에 작은 Gold Accent 아이콘과 함께 현재 사용자에게 부여된 **'권한 레벨'**을 표시합니다. (`Level: Architect`)
    2.  **사용자 프로필/설정 접근:** 우측에 설정 및 로그아웃 버튼 배치.
    3.  **시스템 상태 표시 (Glass Panel):** 전체 대시보드 상단에 얇은 투명 패널로 현재 시스템 연결 상태나 최근 업데이트를 표시합니다.

#### B. 핵심 메트릭 영역 (Core Metrics & Insight)
*   **레이아웃:** 3~4개의 주요 KPI를 카드 형태로 배치하여 시각적 계층을 형성합니다.
*   **구성 요소 (Glass Cards):** 각 카드는 `Secondary Background` 위에 투명도가 적용된 패널로 구현됩니다.
    1.  **KPI 카드 1: 사용자 유지율 (MAU)**
        *   **Metric:** MAU (Monthly Active Users)
        *   **시각화:** 큰 숫자와 함께 지난 30일 대비 변화율(%)을 Gold Accent 색상으로 강조합니다.
    2.  **KPI 카드 2: 전환 효율 (Conversion Rate)**
        *   **Metric:** Trial-to-Paid Conversion Rate
        *   **시각화:** 현재 달성률과 목표치(30%)를 비교하는 게이지 차트 또는 진행 바 형태로 표시합니다.
    3.  **KPI 카드 3: 시스템 참여도 (System Engagement)**
        *   **Metric:** 핵심 이벤트 완료율 (Onboarding Completion Rate)
        *   **시각화:** 전체 사용자 대비 현재 시스템 접근 권한을 가진 사용자의 비율을 도넛 차트 또는 바 그래프로 표현합니다.

#### C. 시스템 접근 영역 (Action & Flow - The Core)
*   **레이아웃:** 대시보드 하단에 위치하며, 실제 '시스템 구축 권한'에 대한 액션 버튼과 흐름도를 제공합니다.
*   **구성 요소:**
    1.  **권한 요청 카드 (The Call to Action):** 가장 눈에 띄는 패널로 설정되어야 합니다.
        *   **제목:** "시스템 접근 권한 요청"
        *   **내용:** 사용자가 현재 부족한 '권한'을 명시하고, 이를 요청할 수 있는 구체적인 단계(User Flow)를 제시합니다.
    2.  **단계별 흐름도 (Simplified User Flow):** 아래의 섹션 4에서 정의된 순서대로 표시됩니다.

### 3. 디자인 실행 지침 (Execution Directives)

**개발팀 전달 사항:** 모든 데이터 시각화 요소는 **'투명한 유리(Frosted Glass)'** 효과를 기본으로 하며, 핵심 지표와 행동 유도 버튼에만 **골드 액센트(`C6A03A`)** 색상을 적용하여 권위와 신뢰감을 극대화해야 합니다. 배경은 짙은 네이비/블랙 계열을 사용하여 투명한 요소가 더욱 돋보이도록 설정합니다.

### 4. 필수 확인 항목 목록 (User Flow Blueprint)

개발팀이 구현해야 할 사용자 여정 및 시스템 접근 흐름입니다. 이 순서대로 인터페이스와 백엔드 로직을 구축해야 합니다.

| Step No. | 화면/액션 | 사용자 행동 | 시스템 반응 (Backend Logic) | 목적 (Goal) |
| :--- | :--- | :--- | :--- | :--- |
| **1** | **대시보드 진입** | 로그인 후 대시보드 접속 | `session_id` 확인, 권한 레벨 조회 | 시스템 상태 확인 |
| **2** | **권한 부족 인식** | 핵심 KPI(예: 전환율)에 도달하기 위해 필요한 '시스템 접근'이 필요함을 인지 | 권한 미충족 알림 표시 (Glass Panel 경고) | 다음 단계 동기 부여 |
| **3** | **권한 요청 시작** | "시스템 구축 권한 요청" 버튼 클릭 | **[Action]** `request_access` API 호출. 필요한 이벤트 목록(e.g., 'Data Access', 'Feature Unlock')을 명시적으로 요청. | 사용자 의도 정의 |
| **4** | **권한 검토 및 승인** | 관리자/시스템이 요청을 검토하고 권한을 부여 | `permission_review` 상태 변경 (Pending -> Approved) | 신뢰 확보 |
| **5** | **권한 획득 확인** | 시스템에서 권한 획득 알림 수신 | 데이터베이스 권한 테이블 업데이트, 사용자 세션에 새로운 권한 반영 | 성공 피드백 제공 |
| **6** | **대시보드 업데이트** | 권한이 부여된 후 대시보드 재로드 | 모든 KPI 및 접근 가능 기능이 실시간으로 업데이트됨 | 최종 목표 달성 |
